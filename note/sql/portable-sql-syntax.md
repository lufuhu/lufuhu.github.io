如果我们在跨数据库开发，SQL是否可移植就是我们必须关心的问题。尽管ANSI/ISO SQL标准(如：SQL-92、SQL:1999、SQL:2003、SQL:2008)为关系型数据库提供了统一的SQL语法基础，但各数据库(如：MySQL、PostgreSQL、SQL Server、Oracle、SQLite)在SQL实现细节、扩展功能和默认行为上存在着很大差异。下面，我们以MySQL 8.0+、PostgreSQL 10+、SQL Server 2012+、Oracle 12c+、SQLite 3.38+为例，简单地梳理一下，可在五大主流数据库(MySQL、PostgreSQL、SQL Server、Oracle、SQLite)上无差别运行(或仅需要极小调整)的通用SQL有哪些？仅供参考。(所有代码块或表格均可左右滚动)

#### 一、写通用SQL时，我们要遵循的基本原则

我们写SQL时，如果想保证可移植性，在开始具体语法前，先要明确以下原则：  
1、**只使用ANSI SQL标准语法**：优先SQL-92，其次SQL:1999/2003；  
2、**使用标准数据类型**：例如，`INTEGER`,`VARCHAR(n)`,`DATE`,`DECIMAL(p,s)`；  
3、**避免数据库专属函数**：如：`NOW()`,`GETDATE()`,`IFNULL`,`LIMIT`,`TOP`……等等；  
4、**优先使用SQL标准操作符与函数**：如字符串连接使用`||`、日期提取使用`EXTRACT`、当前时间使用`CURRENT_TIMESTAMP`等；  
5、**将非标准功能交由应用层处理**：如分页、ID生成、日期格式化、字符串拼接等；  
6、**事务控制语法通用，但行为依赖存储引擎**：如MySQL的`MyISAM`不支持事务；  
7、**警惕隐式行为差异**：如`LIKE`对大小写的处理、`NULL`比较的三值逻辑等，即使语法通用，语义也可能受配置影响；  
8、**测试驱动兼容性**：在目标数据库上运行我们的SQL，而非仅依赖文档。

#### 二、数据定义语言(DDL)，有限但可用的通用性

##### 1、创建基础表(无自增、无特殊类型)

```sql
-- 通用建表语句：不包含自增主键、JSON、布尔等非标准类型
CREATE TABLE employees (
    id INTEGER NOT NULL,                 -- 标准整型，五大主流数据库均支持
    name VARCHAR(100) NOT NULL,          -- 可变长字符串，Oracle虽以VARCHAR2为主，且VARCHAR目前作为其同义词可用，但Oracle官方不推荐使用VARCHAR，因其未来语义可能变更
    email VARCHAR(255),                  -- 允许为空
    hire_date DATE,                      -- 标准日期类型
    salary DECIMAL(10, 2),               -- 精确数值类型，避免FLOAT精度问题
    PRIMARY KEY (id)                     -- 主键约束，标准语法
);
```

*   `INTEGER`：在五大主流数据库中均被识别为整数类型(等价于`INT`)。
    
*   `VARCHAR(n)`：标准可变长字符串。Oracle虽以`VARCHAR2`为主，但在兼容模式下接受`VARCHAR`。
    
*   `DATE`：表示“年-月-日”，不含时分秒，五大主流数据库一致。
    
*   `DECIMAL(p,s)`：精确数值类型，用在金额等场景，优于`FLOAT`/`DOUBLE`。
    
*   **不包含自增主键**：因各库语法差异极大(MySQL:`AUTO_INCREMENT`，PostgreSQL:`SERIAL`或`GENERATED`，SQL Server:`IDENTITY`，Oracle: 需序列+触发器)，故此处我们交由应用层生成ID。
    

⚠️ 注意：如果需要自增ID，我们建议使用UUID(如：`CHAR(36)`)或Snowflake ID(`BIGINT`)，由应用层生成。

##### 2、创建基础表(含约束支持)

```sql
-- 含UNIQUE与CHECK约束(现代版本通用)
CREATE TABLE employees (
    id INTEGER NOT NULL,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE,               -- UNIQUE约束：五大主流数据库均支持
    hire_date DATE,
    salary DECIMAL(10, 2) CHECK (salary > 0), -- CHECK约束：MySQL 8.0.16+、PostgreSQL、SQL Server、Oracle、SQLite均支持
    PRIMARY KEY (id)
);
```

*   **`UNIQUE`约束**：SQL-92标准，五大主流数据库完全支持。
    
*   **`CHECK`约束**：早期MySQL忽略，但自8.0.16起已强制执行，与其他数据库行为一致。
    
*   **自增ID的新标准方案**：SQL:2011引入`GENERATED ALWAYS AS IDENTITY`，目前：
    

```
 -- `GENERATED ALWAYS AS IDENTITY`的跨数据库支持情况：
 --   PostgreSQL 10+      ✔ 完全支持(还支持GENERATED BY DEFAULT AS IDENTITY，允许手动插入值)
 --   SQL Server 2012+    ✔ 通过`IDENTITY`属性，语义等价
 --   Oracle 12c+         ✔ 
 --   MySQL 8.0.21+       ✔ 2020年7月发布
 --   SQLite              ✘ 不支持
```

我们建议(DDL部分)：如果目标库不含SQLite，我们可以考虑使用`GENERATED ALWAYS AS IDENTITY`作为标准的自增方案。通用建表示例(含自增主键)如下：

```sql
-- 方案1：应用层生成ID(100%通用)
CREATE TABLE employees (
    id CHAR(36) PRIMARY KEY,         -- 存储UUID(应用层生成)
    name VARCHAR(100) NOT NULL
);

-- 方案2：标准自增(如果环境不含SQLite，且MySQL≥8.0.21)
CREATE TABLE employees (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY, -- 标准语法
    name VARCHAR(100) NOT NULL
);

-- ⚠️ 方案3：非标准自增(需数据库适配)
-- 只能在能接受方言差异时使用(如：ORM自动转换)
```

明确最低可用版本，如：使用`GENERATED AS IDENTITY`，我们需要保证MySQL≥8.0.21。

##### 3、删除表

```
-- 完全通用的删除表语句
DROP TABLE employees;
```

*   `DROP TABLE`是SQL-92标准语法，五大主流数据库均支持。
    
*   如果表不存在，部分数据库会报错(如：PostgreSQL、SQL Server)，可通过`IF EXISTS`扩展避免，但该语法**非标准**(MySQL/SQLite支持，Oracle不支持)，故我们不推荐用在通用场景。
    

我们**建议**：在应用层先检查表是否存在，再执行`DROP`，或使用ORM提供的迁移机制。

#### 三、数据操作语言(DML)，高度通用

##### 1、插入单行或多行

```sql
-- 插入多行数据，使用标准VALUES语法和日期字面量
INSERT INTO employees (id, name, email, hire_date, salary)
VALUES 
    (1, 'Alice', 'alice@example.com', DATE '2020-01-15', 75000.00),
    (2, 'Bob',   'bob@example.com',   DATE '2021-03-22', 68000.00);
```

*   **多行**`VALUES`：SQL-92允许，五大数据库均支持(SQLite自3.7.11起支持)。
    
*   **标准日期字面量**：`DATE 'YYYY-MM-DD'`是SQL标准写法，五大数据库均能够正确解析。
    
*   **数值字面量**：`75000.00`会被自动转换为`DECIMAL(10,2)`。
    
*   **列顺序无关**：显式指定列名，避免依赖表结构顺序。
    

优势：无需使用`STR_TO_DATE()`(MySQL)、`TO_DATE()`(Oracle)等非标准函数。

⚠️ 我们**关于`NULL`的重要提醒**：在所有SQL数据库中，`NULL = NULL`的结果是`UNKNOWN`(在布尔上下文中视为`FALSE`)，因此永远无法通过`WHERE col = NULL`匹配空值。我们必须使用`IS NULL`或`IS NOT NULL`。这是SQL三值逻辑的主要特性，我们新手常常出错。

##### 2、更新数据

```sql
-- 更新语句，使用标准WHERE条件和日期字面量
UPDATE employees
SET salary = salary * 1.10          -- 涨薪10%
WHERE hire_date < DATE '2020-01-01'; -- 仅更新2020年前入职员工
```

*   `SET`子句支持表达式计算(`salary * 1.10`)。
    
*   `WHERE`使用标准比较操作符`<`和日期字面量。
    
*   无数据库专属语法，完全兼容五大数据库。
    

##### 3、删除数据

```sql
-- 删除语句，标准WHERE过滤
DELETE FROM employees
WHERE salary < 50000.00;  -- 删除低薪员工
```

*   `DELETE FROM ... WHERE ...`是SQL-92核心语法。
    
*   我们要**注意**：如果我们省略`WHERE`，将删除全表数据(**危险操作**)，但语法本身通用。
    

#### 四、数据查询语言(DQL)，主要通用部分

##### 1、基础SELECT查询

```sql
-- 基础查询：SELECT+FROM+WHERE+ORDER BY
SELECT id, name, email, hire_date, salary
FROM employees
WHERE salary > 60000.00
  AND hire_date >= DATE '2019-01-01'  -- 入职时间在2019年及之后
ORDER BY hire_date DESC, name ASC;    -- 先按入职时间倒序，再按姓名升序
```

*   `SELECT ... FROM ... WHERE ... ORDER BY`是SQL-92的基础查询结构。
    
*   **比较操作符**：`=`,`<>`,`<`,`>`,`<=`,`>=`均标准。
    
*   **逻辑操作符**：`AND`,`OR`,`NOT`通用。
    
*   **排序方向**：`ASC`(升序，默认)、`DESC`(降序)。
    
*   **日期字面量**：`DATE '2019-01-01'`确保跨库一致性。
    

✘ 我们要**避免**：`!=`(虽广泛支持，但`<>`是标准)；`BETWEEN`虽通用，但**边界行为**需注意(包含两端)。

##### 2、基础SELECT查询(含`LIKE`与`CURRENT_TIMESTAMP`)

```sql
-- 使用标准CURRENT_TIMESTAMP和LIKE
SELECT id, name, email
FROM employees
WHERE name LIKE 'A%'                     -- 以A开头(%通配任意字符，_通配单字符)
  AND hire_date >= CURRENT_DATE          -- 标准函数：当前日期(不含时间)
ORDER BY hire_date DESC;
```

*   `CURRENT_TIMESTAMP`，SQL标准函数，返回当前日期时间(含时分秒)，五大数据库均支持：
    

*   MySQL ✔
    
*   PostgreSQL ✔
    
*   SQL Server ✔ 等价于`GETDATE()`，但标准
    
*   Oracle ✔ 等价于`SYSDATE`
    
*   SQLite ✔ 返回ISO8601字符串，但可比较
    

*   `CURRENT_DATE`：仅返回日期部分(`DATE`类型)，同样通用。
    
*   **`LIKE`操作符**：
    

*   通配符`%`(任意长度)和`_`(单字符)为SQL-92标准，五大数据库一致；
    
*   **大小写敏感性**由collation决定：通常PostgreSQL/SQLite默认大小写敏感，MySQL/SQL Server默认不敏感，Oracle取决于NLS设置。我们建议在应用层统一处理或显式使用`UPPER()`/`LOWER()`配合`LIKE`。
    

##### 3、聚合与分组

```sql
-- 聚合查询：使用标准聚合函数和全局GROUP BY
SELECT 
    COUNT(*) AS total,                -- 总人数
    AVG(salary) AS avg_salary,        -- 平均薪资
    MIN(hire_date) AS earliest_hire   -- 最早入职日期
FROM employees
WHERE salary IS NOT NULL              -- 排除薪资为空的记录
GROUP BY ();                          -- SQL:1999标准，表示全局聚合(无分组)
-- 注意：显式写GROUP BY ()符合SQL:1999标准，可以保证在所有数据库中明确表达全局聚合意图，避免在MySQL启用ONLY_FULL_GROUP_BY模式时出错
-- HAVING AVG(salary) > 70000.00;     -- 可选：过滤聚合结果
```

*   **聚合函数**：`COUNT(*)`,`COUNT(col)`,`SUM()`,`AVG()`,`MIN()`,`MAX()`均为SQL标准，五大数据库完全支持。
    
*   `GROUP BY ()`：SQL:1999引入，表示“对整个结果集聚合”，五大数据库均识别(即使省略`GROUP BY`也可以，但显式写出更规范)。
    
*   `HAVING`：用在过滤聚合后的结果，语法通用。
    
*   `IS NOT NULL`：标准空值判断，优于`!= NULL`(后者恒为false)。
    

我们**提示**一下：如果需要按部门分组，可写`GROUP BY department_id`，同样通用。

##### 4、连接(JOIN)

```sql
-- 使用ANSI JOIN语法进行多表连接
SELECT 
    e.name AS employee_name,
    d.department_name
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id    -- 内连接：仅返回匹配记录
LEFT JOIN offices o ON e.office_id = o.id       -- 左连接：保留employees所有记录
WHERE d.location = 'New York';                  -- 过滤部门位置
```

*   `INNER JOIN`/`LEFT JOIN`/`RIGHT JOIN`：SQL-92标准连接语法，五大数据库均支持。
    
*   **必须使用`ON`子句**：我们要避免旧式逗号连接(`FROM a, b WHERE a.id = b.id`)，虽然可以用，但不符合现代标准。
    
*   **表别名**：`e`,`d`,`o`提高可读性，通用。
    
*   **连接条件**：`ON e.dept_id = d.id`是标准等值连接。
    

✘ 我们要**避免**：`FULL OUTER JOIN`虽标准，但**MySQL不支持**，所以没有列入通用子集。

##### 5、条件表达式(CASE)

```sql
-- 使用标准CASE表达式进行条件分支
SELECT 
    name,
    CASE 
        WHEN salary >= 100000 THEN 'High'    -- 高薪
        WHEN salary >= 70000  THEN 'Medium'  -- 中薪
        ELSE 'Low'                           -- 低薪
    END AS salary_level
FROM employees;
```

*   `CASE WHEN ... THEN ... ELSE ... END`是SQL标准条件表达式。
    
*   五大数据库均完全支持，且行为一致(从上到下匹配，首次命中即返回)。五大数据库均支持简单`CASE`表达式(`CASE col WHEN val1 THEN...`)和搜索`CASE`表达式(`CASE WHEN condition THEN...`)，这两种形式都是标准且通用的。
    
*   可用在`SELECT`、`WHERE`、`ORDER BY`等任何表达式位置。
    

优势：替代`IIF()`(SQL Server)、`DECODE()`(Oracle)等非标准函数。

##### 6、条件表达式(CASE，含`EXTRACT`函数)

在“窗口函数”或“CASE”示例中，我们可以加入：

```sql
-- 使用EXTRACT提取日期部分(SQL标准)
SELECT 
    name,
    EXTRACT(YEAR FROM hire_date) AS hire_year,
    CASE 
        WHEN EXTRACT(YEAR FROM hire_date) >= 2020 THEN 'New'
        ELSE 'Legacy'
    END AS cohort
FROM employees;
```

*   `EXTRACT(part FROM datetime)`是SQL:1999标准函数，用在从日期时间中提取年、月、日等部分。
    
*   EXTRACT**兼容性**：五大数据库均支持`EXTRACT(YEAR/MONTH/DAY FROM date)`，但SQLite 3.38+才支持完整时间部分，在SQLite中，EXTRACT要求日期值为标准ISO8601字符串格式，否则可能无法正确解析。
    
*   **优于**：`YEAR()`(MySQL)、`DATEPART()`(SQL Server)、`TO_CHAR(..., 'YYYY')`(Oracle)等非标准函数。
    

##### 7、空值处理(COALESCE)

```sql
-- 使用COALESCE处理空值(标准函数)
SELECT 
    COALESCE(email, 'no-email@example.com') AS contact_email,  -- 如果email为空，用默认值
    name
FROM employees;
```

*   `COALESCE(val1, val2, ..., valN)`返回第一个非空值。
    
*   是SQL标准函数，五大数据库均支持。
    
*   **优于**：`IFNULL()`(MySQL)、`ISNULL()`(SQL Server)、`NVL()`(Oracle)。
    

我们**推荐**做法：统一使用`COALESCE`处理空值逻辑。

##### 8、字符串连接：标准`||`的兼容性

前面，我们建议“由应用层拼接”，但值得指出：

SQL标准定义`||`为字符串连接操作符。实际上，PostgreSQL、Oracle、SQLite、SQL Server：默认支持`a || b`；MySQL：默认将`||`视为逻辑`OR`，但可通过设置`SET sql_mode = PIPES_AS_CONCAT;`启用标准行为。因此，在可控环境下(如：内部系统、可配置MySQL模式)，`||`可以作为通用连接符：

```sql
SELECT first_name || ' ' || last_name AS full_name FROM employees;
```

在Oracle中，`||`连接`NULL`值时，结果为非`NULL`值(`NULL || 'a'`结果为`a`)(如图所示)，而在其他部分数据库中可能结果不同。

#### 五、高级通用特性

在目标数据库版本满足的前提下(如：SQLite≥3.25，MySQL≥8.0)，以下高级特性也可以视为通用。

##### 1、非递归CTE(公用表表达式)

```sql
-- 非递归CTE：用在逻辑分层，提高可读性
WITH high_earners AS (
    SELECT id, name, salary
    FROM employees
    WHERE salary > 80000
)
SELECT * FROM high_earners
ORDER BY salary DESC;
```

**兼容性**：

*   PostgreSQL ✔
    
*   SQL Server 2005+ ✔(2012+更稳定)
    
*   Oracle 9i+ ✔
    
*   MySQL 8.0+ ✔
    
*   SQLite 3.8.3+ ✔
    

结论：只要目标数据库版本满足，**非递归CTE可安全用于通用SQL**。

##### 2、窗口函数(SQL:2003)

```sql
-- 窗口函数：用于排名、累计、移动平均等
SELECT 
    name,
    salary,
    RANK() OVER (ORDER BY salary DESC) AS salary_rank,
    SUM(salary) OVER (ORDER BY hire_date ROWS UNBOUNDED PRECEDING) AS running_total
FROM employees;
```

**兼容性**：

*   PostgreSQL ✔
    
*   SQL Server 2012+ ✔
    
*   Oracle 8i+ ✔(功能完整)
    
*   MySQL 8.0+ ✔
    
*   SQLite 3.25+ ✔(2018年后版本)
    

结论：在现代项目中，窗口函数应该纳入通用SQL能力范围。

#### 六、事务控制(TCL)，语法通用，行为依赖引擎

```sql
-- 事务控制：BEGIN/COMMIT/ROLLBACK
BEGIN TRANSACTION; 
-- 或BEGIN TRAN(SQL Server/Sybase)
-- 或仅写BEGIN(PostgreSQL/SQLite/MySQL/Oracle)
UPDATE accounts SET balance = balance - 100 WHERE user_id = 1;
UPDATE accounts SET balance = balance + 100 WHERE user_id = 2;
COMMIT; -- 提交事务

-- 若出错，可执行：
-- ROLLBACK; -- 回滚事务
```

*   `BEGIN`,`COMMIT`,`ROLLBACK`是SQL标准事务控制语句。
    
*   **兼容性**：
    

*   PostgreSQL、SQLite、Oracle：使用`BEGIN`。
    
*   MySQL：InnoDB引擎支持，且兼容`BEGIN`(也可以用`START TRANSACTION`)。
    
*   SQL Server：使用`BEGIN TRANSACTION`(或`BEGIN TRAN`)，直接写`BEGIN`会报语法错误。准确来说，SQL Server中`BEGIN`本身是合法的，但它用在流程控制(如：`BEGIN...END`块)，而非事务开始。
    

*   **注意**：MyISAM(MySQL)、MEMORY等引擎不支持事务，但语法仍可执行(无实际效果)。
    

我们**建议**：在支持事务的引擎上使用，确保数据一致性。

#### 七、递归查询(SQL:1999)，需微调关键字

```sql
-- ⚠️ 递归CTE：需注意RECURSIVE关键字的兼容性
WITH RECURSIVE org_tree AS (
    -- Anchor member: 根节点(无上级)
    SELECT id, parent_id, name, 0 AS level
    FROM org
    WHERE parent_id IS NULL

    UNION ALL

    -- Recursive member: 递归查找子节点
    SELECT o.id, o.parent_id, o.name, ot.level + 1
    FROM org o
    INNER JOIN org_tree ot ON o.parent_id = ot.id
)
SELECT * FROM org_tree
ORDER BY level, id;
```

*   **通用性**：MySQL 8.0+：**必须**写`RECURSIVE`；PostgreSQL/SQLite：`RECURSIVE`可省略，但保留也合法；SQL Server/Oracle：**不能写**`RECURSIVE`，否则报错。
    
*   我们**建议**：在应用层根据数据库类型动态决定是否包含`RECURSIVE`；或避免递归，改用路径枚举、闭包表等替代方案。
    

如果我们严格要求“一条语句五大数据库通用”，严格限制“无修改运行”，那么递归查询**不属于通用子集**。

#### 八、分页查询(SQL:2008 标准)，部分支持

```sql
-- ⚠️ SQL:2008标准分页(非全库支持)
SELECT id, name, salary
FROM employees
WHERE salary > 50000
ORDER BY salary DESC
OFFSET 10 ROWS           -- 跳过前10行
FETCH NEXT 10 ROWS ONLY; -- 取接下来10行
```

*   **支持情况**：
    

*   ✔ PostgreSQL 8.4+
    
*   ✔ SQL Server 2012+
    
*   ✔ Oracle 12c+
    
*   ✔ DB2
    
*   ⚠️ MySQL 8.0.30+才支持`OFFSET ... FETCH`，且必须配合ORDER BY，否则报错：
    
    ```
     /* MySQL 8.0.30+注意事项：
      - 必须写ORDER BY，否则报错"ERROR 1064 (42000)"
      - 早期版本需改用LIMIT/OFFSET
     */
    ```
    
*   ✘ **SQLite**：不支持`OFFSET ... FETCH`(但支持`LIMIT 10 OFFSET 10`)
    

如果目标库包含MySQL<8.0.30或SQLite，则此语法**不通用**。此时，我们可选择在应用层单独编写适配逻辑，或借助ORM的方言机制处理分页。我们需要明确的是：**不存在真正通用的分页方案**，必须通过抽象层（如：ORM框架）来屏蔽数据库差异，实现跨库兼容。

#### 九、其他通用特性

##### 1、字符串与注释

```sql
-- 字符串字面量：单引号，转义用两个单引号
SELECT 'O''Brien' AS name;  -- 结果：O'Brien

-- 注释：单行与多行
-- 这是单行注释
/* 这是
   多行注释 */
```

##### 2、标识符引用

```sql
-- 使用双引号引用标识符(如：保留字、大小写敏感)
SELECT "order", "User" FROM "Table"; 
-- 注意：MySQL默认用反引号``，需要开启ANSI_QUOTES模式才支持双引号
```

##### 3、布尔与子查询

```sql
-- EXISTS子查询(通用)
SELECT name FROM employees e
WHERE EXISTS (
    SELECT 1 FROM orders o WHERE o.employee_id = e.id
);

-- IN/NOT IN(通用)
SELECT * FROM employees WHERE id IN (1, 2, 3);
```

##### 4、标准字符串函数(SQL-92)

```sql
-- TRIM, UPPER, LOWER是SQL-92标准函数
SELECT 
    TRIM(name) AS trimmed_name,
    UPPER(email) AS upper_email,
    LOWER(name) AS lower_name
FROM employees;
```

五大数据库均支持这些函数，可用在数据清洗。

##### 5、行值构造器(Row Value Constructor)

```sql
-- 用在多列比较的标准语法，五大数据库均支持
SELECT * FROM employees
WHERE (dept_id, salary) IN (
    SELECT dept_id, MAX(salary) 
    FROM employees 
    GROUP BY dept_id
);
```

*   支持用`(col1, col2)`形式进行多列组合比较，替代需关联多次的复杂逻辑。
    
*   等价于"每个部门中薪资最高的员工"，比传统子查询更简洁。
    
*   完全兼容MySQL 8.0+、PostgreSQL、SQL Server 2016+、Oracle、SQLite 3.15+。
    

##### 6、标准数学函数

```sql
-- 基础数学函数的通用子集
SELECT
    ABS(-100) AS absolute_value,       -- 绝对值
    MOD(10, 3) AS modulus,             -- 取余(等价于10%3)
    POWER(2, 3) AS power_result,       -- 幂运算(2^3)
    ROUND(3.14159, 2) AS rounded      -- 四舍五入
FROM employees;
```

*   上述函数为SQL标准定义，五大数据库行为一致
    
*   我们避免使用`FLOOR()`/`CEIL()`以外的扩展函数(如：`LOG()`参数顺序各库不同)
    

##### 7、空值安全比较(IS NOT DISTINCT FROM)

```sql
-- 处理NULL=NULL场景的标准语法
SELECT * FROM employees e1
JOIN employees e2 
  ON e1.email IS NOT DISTINCT FROM e2.email;
```

*   等价于`(e1.email = e2.email OR (e1.email IS NULL AND e2.email IS NULL))`。
    
*   支持情况：PostgreSQL ✔、SQL Server 2022+ ✔、Oracle 12c+ ✔、MySQL ✘(截至 8.0.39 仍不支持)、SQLite 3.24+ ✔。
    
*   解决了`NULL = NULL`返回`UNKNOWN`的经典问题，比自定义逻辑更简洁。
    

##### 8、表值构造器(Table Value Constructor)

```sql
-- 生成临时数据集的标准方式
SELECT * FROM (
    VALUES 
        (1, 'Sales'), 
        (2, 'Engineering'),
        (3, 'HR')
) AS departments(id, name);
```

*   无需创建临时表，即可生成虚拟数据集，用在测试或关联查询。
    
*   支持情况：PostgreSQL ✔、SQL Server ✔、Oracle 12c+ ✔、MySQL 8.0.19+ ✔、SQLite 3.33+ ✔。
    

##### 9、FETCH FIRST(简化分页写法)

```sql
-- 比OFFSET...FETCH更简洁的标准分页
SELECT * FROM employees
ORDER BY hire_date
FETCH FIRST 5 ROWS ONLY;  -- 取前5行
```

*   是`OFFSET 0 ROWS FETCH NEXT 5 ROWS ONLY`的简化版。
    
*   支持情况同`OFFSET...FETCH`，但语法更简洁。
    
*   我们可加`WITH TIES`返回同排名数据(需数据库支持，如：SQL Server、Oracle)。
    

#### 十、通用SQL能做什么？

##### 1、复杂报表(多层聚合+CASE+JOIN)

```sql
SELECT 
    d.region,
    COUNT(e.id) AS headcount,
    AVG(e.salary) AS avg_salary,
    SUM(CASE WHEN e.salary > 100000 THEN 1 ELSE 0 END) AS high_earners
FROM departments d
LEFT JOIN employees e ON d.id = e.dept_id
GROUP BY d.region
HAVING COUNT(e.id) > 5
ORDER BY avg_salary DESC;
```

五大数据库通用，无需任何修改。

##### 2、数据清洗(COALESCE+TRIM+UPPER)

```sql
SELECT 
    COALESCE(TRIM(UPPER(name)), 'UNKNOWN') AS clean_name,
    COALESCE(email, 'no-email') AS contact
FROM raw_users
WHERE name IS NOT NULL;
```

`TRIM()`,`UPPER()`,`LOWER()`，在五大数据库中，均支持。

##### 3、存在性检查+批量插入(UPSERT的通用替代)

```sql
-- 先删除(如果存在)
DELETE FROM target WHERE id IN (SELECT id FROM staging);

-- 再插入
INSERT INTO target (id, name)
SELECT id, name FROM staging;
```

两步操作，完全通用，适用于大多数“幂等写入”场景。

##### 4、窗口函数实现累计与排名

```sql
SELECT 
    name,
    hire_date,
    salary,
    RANK() OVER (PARTITION BY EXTRACT(YEAR FROM hire_date) ORDER BY salary DESC) AS annual_rank,
    SUM(salary) OVER (ORDER BY hire_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
FROM employees;
```

在满足版本要求的五大数据库中，完全通用。

##### 5、CTE构建中间结果集用于多层逻辑

```sql
WITH filtered_employees AS (
    SELECT id, name, dept_id, salary
    FROM employees
    WHERE salary > 60000
),
dept_stats AS (
    SELECT dept_id, AVG(salary) AS dept_avg
    FROM filtered_employees
    GROUP BY dept_id
)
SELECT 
    fe.name,
    fe.salary,
    ds.dept_avg
FROM filtered_employees fe
JOIN dept_stats ds ON fe.dept_id = ds.dept_id
ORDER BY fe.salary DESC;
```

非递归CTE链式调用，五大数据库通用。
